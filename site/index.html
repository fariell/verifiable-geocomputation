让空间计算的每一步
推理都可被机器证明

Verifiable Geocomputation(可验证空间计算)把 AI 在数学定理证明上爆发的能力——DeepSeekMath-V2、Lean、Dafny、形式化基准——迁移到地理空间分析:让 DEM 地形分析、空间算子、变化检测的每一步输出,都可被形式化规范定义、机器证明检验、并最终可被自主发现。

问题

空间分析软件今天长这样

我们每天用 GDAL、WhiteboxTools、ArcGIS、TauDEM 跑上亿次空间算子——但从来没人能告诉你,这次计算的结果是不是对的。

现状

算子文档说"用 Horn 法算坡度",但 5 个实现跑出 5 个略有差异的结果。论文说"流向判定准确率 96%",但剩下 4% 错在哪、什么时候错、为什么错——没人能回答。审稿人质疑结论时,你只能"再跑一遍看看"。

"结果可信但过程不可验证"——空间计算是黑箱。

我们的命题

同样的范式迁移,在数学定理证明领域已经发生:DeepSeekMath-V2 用"验证器-生成器"双模型架构拿到 IMO 金牌;Numina-Lean-Agent 用编码智能体解完 Putnam 2025。

这套范式从来没有被认真搬到空间分析。我们要做这件事——让空间算子的每一步,都有 Lean/Dafny 证明背书。

"空间计算结果的可验证性,能否被形式化地定义、证明与机器检验?"
— 这是我们整条研究路线要回答的一个问题
思路

三层资产结构

只发论文 = 高级论文工人。只做基准/库 = 在考核里活不到成型。必须三线并行,让论文从资产中自然产生——每发一个版本就有一篇论文,每跑一次基准就有一篇分析。

L1 · 流量层

论文

可见度与考核指标的硬通货。容易做,但不构成壁垒,可被绕过。

代表产出: 形式化 DEM 算子论文、GeoProofBench 基准论文、可验证性度量论文。
L2 · 壁垒层

开源库 + 基准

VeriGIS 库、GeoProofBench 命题库、排行榜。别人引用你的真正原因。

代表产出: VeriGIS Python 包(Lean 绑定)、GeoProofBench v1 (300 命题)、持续更新的排行榜。
L3 · 复利层

方向与社区

Special Issue、Workshop、标准提案、研究生梯队、编委身份。从"做研究"到"立方向"。

代表产出: IJGIS Special Issue、OGC 可验证性议题提案、ISPRS Summer School。
飞轮

体系自我造血的四个齿轮

这是体系区别于"一组相关论文"的核心结构。飞轮启动的标志是:智能体自动发现一条新的空间性质,经人工核验后写回规范库——这件事一旦发生,体系就真正转起来了。

资产

正在筹建的四块核心产出

每一个都既是论文的载体,也是别人引用我们的真正原因。这是 L2 壁垒层的具体内容。

VG
VeriGIS
筹建

一个 Python 包,把 GDAL/WhiteboxTools 等成熟空间库的算子接口暴露为可形式化规范的形式:每个函数都附带 Lean/Dafny 形式规约、属性测试、与参考实现的差分验证。

→ 查看 library/
GB
GeoProofBench
v0 启动

首个面向 DEM 空间推理的形式化定理证明基准:300 条经典命题(坡度/水文/可视域/变化检测),双语言形式化(Lean 4 + Dafny),公开排行榜,持续扩充。

→ 查看 benchmark/
F4
Formal Specs
设计阶段

Lean 4 + Dafny 双形式化规范库:定义核心 DEM 算子的形式语义,证明算子性质(单调性、对称性、环流守恒等),可机器检验。

→ 查看 formal/
GA
GeoMath-Agent
Y2 启动

基于通用编码智能体的空间定理证明器与发现器:可自主检索定理、生成证明、调用 GIS 工具验证、提出反例。是飞轮的引擎,Y2 启动。

如何加入这个方向

项目处于 Y0 早期,**欢迎任何形式的贡献**——你的每一步都是体系的一部分。

提命题

你熟悉的某条 DEM 几何/水文性质——能写成一句话"对所有满足 X 的 DEM,输出 Y 满足 Z"的形式——就是 GeoProofBench 的素材。提 issue 即可。

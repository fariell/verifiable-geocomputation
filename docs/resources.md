## 二、关键判断:这个方向的瓶颈不是 GPU

这一点必须先说清楚,否则很容易把钱花错地方。可验证空间计算有三类负载,**只有第三类才真正吃 GPU,而它排在 Y3 之后**:

| 负载 | 干什么 | 真实瓶颈 | 需要 GPU 吗 |
| --- | --- | --- | --- |
| **A. 形式化编译与证明检查** | `lake build`、Lean/Dafny 证明校验、Z3 反例搜索 | **CPU 单核性能 + 内存**(首次构建 mathlib 30–60 min) | ❌ 完全不需要 |
| **B. LLM 推理与评测** | 命题 → 生成证明 → 校验器判定 | **API 费用与并发**,不是本地算力 | ❌ 走 API;本地跑 7B 量化模型做对照才用 |
| **C. DEM 批处理** | 坡度/曲率/汇流累积、多时相差值 | **内存 + 磁盘 IO**(单景 30m DEM 可达数 GB) | ❌ 一般不需求 GPU(除非训练) |
| **D. 模型训练** | 微调证明器模型(D3 自主定理发现) | 显存 | ✅ **但属于 Y3+ 扩张期** |

**结论:RTX 3080 + AutoDL 经费,对 Y0–Y2 的全部计划已经过剩。**
真正的稀缺资源是另两样:**人工核验命题的时间**,以及 **API 预算**。请把注意力放在这两处。

> 顺带一句:这也是"一人科研"能成立的根本原因——这个方向恰好是**对人手不敏感、对判断力敏感**的那一类研究。

## 三、成本测算(GeoProofBench 评测,P2 论文的核心开销)

假设(请按实际 API 定价复核):

- 单条命题:输入约 3k tokens(命题 + 上下文 + few-shot),输出约 1.5k tokens(证明)
- 评测算例:300 条命题 × 5 个模型 × pass@8(8 次采样)
- 采样次数 = 300 × 5 × 8 = **12 000 次**

| 项 | 估算 |
| --- | --- |
| 输入 tokens | ~36 M |
| 输出 tokens | ~18 M |
| 单次全量评测(按输入 ¥2/M、输出 ¥8/M 估) | **约 ¥220** |
| 加迭代、失败重试、agent 多轮开销(×5) | **约 ¥1 000 – 2 000** |

**对比:一篇 MDPI *Remote Sensing* 的 APC 约 ¥2 000–2 500。**
也就是说,**整个基准评测的 API 成本,不到一篇 OA 版面费**。这个数字在写基金预算时可以理直气壮地列。

预算建议(Y0 一年):

| 用途 | 建议 | 说明 |
| --- | --- | --- |
| LLM API | ¥3 000 – 5 000 | 评测 + agent 日常,按月设上限,避免失控 |
| AutoDL 云主机 | ¥2 000 – 4 000 | **留到 Y2 GeoMath-Agent 再用**,Y0 基本用不上 |
| OA 版面费 | ¥5 000 – 8 000 | 2–3 篇 MDPI/Scientific Data |
| 合计 | **约 ¥1.5 万** | 与青C 直接经费(约 30 万)相比极小,主要用于换取时间 |

## 四、本机 vs AutoDL 分工

| 场景 | 用哪里 | 理由 |
| --- | --- | --- |
| Lean 4 / mathlib 构建与证明检查 | **本机** | 增量编译,常驻最快;放云上每次重传反而慢 |
| 日常编码、写文档、agent 协作 | **本机** | 迭代频繁 |
| 小模型对照实验(7B 量化) | **本机 3080** | 显存够(Q4 量化 7B 约需 6–8 GB) |
| 多模型批量评测(并发、长时间) | **AutoDL** | 本机挂机一周不现实,云上跑完拉结果 |
| 全球尺度 DEM 批处理(大内存) | **AutoDL 大内存机型** | 需 64 GB+ 内存 |
| 模型微调(D3,Y3+) | **AutoDL 多卡** | 真正需要 GPU 时再上 |

**环境建议(重要)**:

- 本机是 Windows。**Lean 4 / GDAL / WhiteboxTools / vLLM 在原生 Windows 上都别扭**,建议装 **WSL2 + Ubuntu 22.04**,把开发环境整体放进去;Windows 侧只留 Office、浏览器、文献管理。
- vLLM 不支持 Windows 原生,要本地推理必须走 WSL2 或直接用 API。
- 按此配置,形式化与地理数据处理在同一环境内,避免两套工具链来回切换。

## 五、两条必须提前说清的风险

### 1. 数据合规(请务必重视)

依托单位为西北核技术研究所。**任何内部数据、涉密数据、未公开数据源一律不得上传至 AutoDL 或任何公有云平台。**

执行原则:

- 云上**只用公开 DEM 数据**(Copernicus DEM、ALOS AW3D30、TanDEM-X、NASADEM、MERIT DEM、ArcticDEM)
- 代码开源前自检:不含内部路径、不含未公开数据源、不含敏感参数
- 论文与基准数据集全部基于公开数据构建,可无顾虑地随论文公开

这一条不是形式主义——它决定了这套成果能不能长期公开、能不能作为体系的基础。

### 2. 不要把 AutoDL 经费烧在训练上

Y0–Y2 训练模型的边际收益极低:我们要证明的是"可验证性",不是"我们的模型更强"。**经费留到 Y2 做 GeoMath-Agent 的批量评测**,那才是真正需要算力的地方。

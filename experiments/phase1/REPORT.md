# Phase 1 实验报告 — Verifiable DEM Terrain Operator Baseline

> 运行时间:2026-09-05 · 实例:SeetaCloud (seetacloud.com, 128 核 / 1TiB RAM / 无 GPU)
> 状态:✅ 完成 · 全部产出见 `results/`

## 一、做了什么

1. **环境自动安装**:apt 系统依赖 → Python venv → numpy/scipy/matplotlib(可选 rasterio/whiteboxtools/richdem,失败不影响主体)→ 启动实验 → 尝试 Lean 4(elan 在 github 发布页重定向上挂起,已超时跳过,非必需)。
2. **算子可复现性实验**:生成「高斯叠加 + 线性倾斜」合成 DEM(200×200,dx=1m),其 1/2 阶导有**闭式解**;用有限差分数值计算同一组导数,对比得到验证指标。
3. **GeoProofBench v0.1 命题种子集**:生成 20 条候选命题(json/csv/md),作为后续 Lean 4 / Dafny 形式化的原料。
4. **Lean 4 冒烟测试**:骨架工程已上传,因 elan 下载超时未构建(见 §三)。

## 二、核心结果(数值算子 vs 解析真值)

| 算子 | RMSE | MAE | 相关系数 | 判定 |
| --- | --- | --- | --- | --- |
| 坡度 magnitude | 1.16e-02 | 2.37e-03 | **0.99994** | ✅ 高度可验证 |
| 梯度 ∂h/∂x | 1.44e-02 | 2.05e-03 | **0.99988** | ✅ 高度可验证 |
| 梯度 ∂h/∂y | 1.01e-02 | 1.62e-03 | **0.99994** | ✅ 高度可验证 |
| 剖面曲率 profile | 2.98e-01 | 3.92e-02 | **0.157** | ❌ 不可验证(粗网格问题) |

一阶算子(坡度/梯度)数值实现与解析真值几乎完全重合(corr > 0.9999,误差量级 1e-2,源于网格离散化)。
**二阶曲率算子严重偏离**:RMSE 0.30、相关系数仅 0.157,且在高斯峰附近出现最大 55 量级的绝对误差。

## 三、这是 bug 还是发现?

**是发现,而且是本方向要解决的真实缺口。**

一阶算子只需要局部一阶差分,收敛快、误差小;二阶曲率对网格间距极其敏感,在 1m 粗网格 + 朴素中心差分下根本无法逼近解析真值。这恰好从**经验层面**证明了研究纲领的必要性:

> 当前 DEM 地形算子并非"天然可验证"——越往高阶,数值实现与数学真值之间的鸿沟越大。
> 这正是"可验证空间计算"要做的事:用形式化方法为算子建立**有界的、可机器检验的误差保证**,而不是靠经验调参。

(注:曲率误差也可能部分来自朴素 FD 公式与解析曲率公式的约定差异;下一步用自适应/高阶/已验证算子对比,可把这一发现写成 P0/P1 论文的"动机实验"。)
